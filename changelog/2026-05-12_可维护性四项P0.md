# 可维护性四项 P0 改进

来源：Opus 4.7 《AI 开发团队 — 可维护性改进规划》优先级矩阵建议

## 1. 熔断器（Circuit Breaker）
- 新文件：`references/circuit_breaker.py`
- 60s 窗口内 5 次失败自动熔断，写入 `state/CIRCUIT_OPEN.flag`
- `model_adapter.py` 的 `call_role()` 检查熔断状态，打开时直接抛异常（不发 HTTP 请求）
- 30 分钟自动恢复或手动删除标志文件
- 调用链：`call_role() → get_breaker().is_open() → 拒绝/放行`

## 2. 启动健康检查
- 新文件：`references/health_check.py`
- 7 项检查：角色文件 / API Key / knowledge 目录 / schema 版本 / 端口 / logs 可写 / 依赖
- `server.py` 的 `main()` 启动前调用 `preflight_check()`，失败则 `sys.exit(1)`

## 3. 统一结构化日志
- 新文件：`references/logger.py`
- JSONL 格式 + stdout 双输出
- 字段：ts / project_id / role / dispatch_id / phase / event
- `runner.py` 接入点：task_started / task_completed / task_timeout / task_failed / sub_request_spawned / phase_change / project_started / project_completed
- 查询：`jq '.role == "frontend"' logs/proj_xxx.jsonl`

## 4. 配置与代码分离
- 新建 `config/` 目录，三个 YAML 文件：providers.yaml / roles.yaml / workflow.yaml
- 新文件：`references/config_loader.py`（带环境变量 `${VAR:-default}` 展开）
- `model_adapter.py` 和 `runner.py` 优先从 YAML 读取，硬编码值作为 fallback
- 改 timeout / 模型 / provider 不再需要改 .py 文件

## 改动文件
- 新增：config/providers.yaml, config/roles.yaml, config/workflow.yaml
- 新增：references/circuit_breaker.py, references/config_loader.py, references/health_check.py, references/logger.py
- 修改：references/model_adapter.py（熔断器集成 + YAML 加载）
- 修改：references/runner.py（workflow YAML + 结构化日志事件）
- 修改：server.py（启动健康检查）
- 修改：.gitignore（排除 logs/）
