# 第三轮优化修复

**日期**: 2026-05-12
**类型**: 修复 + 增强

---

## P1: DAG 失败阻断机制

**文件**: `references/runner.py`

**问题**: 当上游任务失败时，下游依赖任务仍然执行，浪费 API 调用。

**修复**:
- `run_dag()` 新增 `failed_ids` 追踪失败任务 ID
- 每层执行前检查每个任务的 `depends_on` 是否包含失败 ID
- 依赖未满足的任务直接标记为 `blocked`，跳过执行
- 失败日志改进：输出具体失败的任务名和将被阻断的下游

**影响**: 上游关键任务失败时，后续层不会盲目继续，节省 token 消耗。

---

## P2: DAG 审批超时一致性

**文件**: `references/runner.py`

**问题**: `_request_dag_approval()` HTTP 模式超时后 `dec.get("approved", True)` 自动批准，但 `_request_human_approval()` 超时后是自动拒绝（`False`），不一致。

**修复**: DAG 审批超时默认改为 `dec.get("approved", False)` — 超时自动拒绝，与执行审批一致。

---

## P2: API Key 缺失友好提示

**文件**: `references/model_adapter.py`

**问题**: `os.environ["KEY"]` 直接访问，KeyError 对新用户不友好。

**修复**:
- 新增 `_require_env(key, provider_name)` 辅助函数
- 缺失时抛出 `RuntimeError` 并给出明确的设置指引
- 所有 provider（DeepSeek、Claude、OpenAI、Gemini）统一使用

---

## P2: 服务恢复异常日志

**文件**: `server.py`

**问题**: `_run_async_task()` 中断点恢复的 `except Exception: pass` 静默吞掉所有异常。

**修复**: 改为 `except Exception as e: logger.warning(...)` 输出警告信息。

---

## P3: DBA Temperature 调整

**文件**: `references/model_adapter.py`

**问题**: DBA 在所有 provider 中 temperature=0.0，某些模型在绝对确定性 temperature 下可能产生重复输出。

**修复**: DeepSeek/Claude/OpenAI/Gemini 的 DBA temperature 统一改为 0.1（any provider 已为 0.1）。

---

## P3: 知识库种子数据

**文件**: `references/knowledge_base.py`

**问题**: 知识库初始化后 getchas.md 为空，新项目启动时没有任何参考。

**修复**:
- 新增 `_default_gotchas()` 函数，种子 3 条常见坑：
  1. 大模型输出格式不稳定（JSON 解析容错）
  2. Sub_requests 循环爆炸（深度限制）
  3. 工具调用死循环（max_iter 硬上限）

---

## P3: UX Sub_request 模板改进

**文件**: `references/roles/ux.md`

**问题**: UX prompt 模板中 `<sub_requests>` 块直接出现在 response 区域，UX 可能直接复制示例导致误触发。

**修复**: 添加 `[可选]` 标记和「不需要则删除整个块」提示，降低误触发率。
