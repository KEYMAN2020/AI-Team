## P0-1: build_tools_prompt 缺失导入 — 致命 NameError

**文件**: `references/model_adapter.py`

**严重性**: 每次调用任何角色都会崩溃。`load_system_prompt()` → `build_tools_prompt(role)` 但该函数从未导入。

**修复**: import 行添加 `build_tools_prompt`，删除未使用的 `get_tool_names_for_role`。

---

## P0-2: file_write 路径穿越漏洞

**文件**: `references/tools_registry.py`

**问题**: LLM 可通过 `../../.env` 或 `/etc/passwd` 覆盖任意文件，无任何路径校验。

**修复**: `_exec_file_write()` 使用 `Path.relative_to()` 校验目标路径在 `cwd` 内，越界直接拒绝。

## P1-1: DAG 审批外超时不一致

**文件**: `references/runner.py`

**问题**: `_request_dag_approval()` 外层超时（3600s内无任何文件）返回 `True`（自动批准），
而 `_request_human_approval()` 超时返回 `False`（自动拒绝），行为不一致。

**修复**: 统一改为超时自动拒绝。日志 `自动批准` → `自动拒绝`，`return True` → `return False`。

## P3-3: Bash code_run 绕过安全扫描

**文件**: `references/tools_registry.py`

**问题**: `_exec_code_run(language="bash")` 使用 `bash -c`（等效 shell=True），但只检查 Python pattern，不检查 bash 危险命令。

**修复**: 新增 `_check_dangerous_bash_code()` 函数，扫描 bash 代码中的危险命令和模式（如 `rm -rf`, `dd if=`, 重定向到 /dev/ 和 /etc/）。code_run 中 bash 语言先过 Python pattern 再过 bash 专用检查。
