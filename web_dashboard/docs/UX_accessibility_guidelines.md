# 适老化设计原则草案（UX Accessibility Guidelines）

## 文档目标
本草案用于指导产品在“老年用户友好”场景下的交互与视觉设计，重点覆盖：**字号、对比度、点击热区、流程简化、错误提示与引导**。目标是在不显著增加学习成本的前提下，提升可读性、可操作性与任务完成率。

---

## 1. 字号与排版（Readable Typography）

### 1.1 基础字号建议
- **正文最小字号：16px（移动端）/ 16–18px（Web）**，推荐默认 18px。
- **二级信息：不低于 14px**（如辅助说明、时间戳）。
- **页面标题：24–28px**，分组标题：20–22px。
- 行高建议 **1.5–1.8 倍**，避免文字拥挤。

### 1.2 字体与样式
- 优先使用清晰的无衬线字体（如系统默认字体族）。
- 避免过细字重（不低于 Regular/400）。
- 避免整段斜体、全大写、花体。
- 控制每行字数（移动端建议 14–22 个汉字）以减少视觉疲劳。

### 1.3 可调节能力
- 提供“**字体大小切换**”（标准/大号/超大）入口，且全局生效。
- 字号放大后页面不应出现内容截断、按钮重叠、关键功能被折叠。

**设计理由**：老年用户常见近距视力下降，较大字号与更宽松行距可显著降低阅读负担，提高理解速度。

---

## 2. 对比度与视觉可辨识性（Contrast & Legibility）

### 2.1 对比度标准
- 正文与背景对比度 **≥ 4.5:1**（WCAG AA）。
- 大字号文字（≥24px 或 ≥18.66px 粗体）对比度 **≥ 3:1**。
- 关键操作按钮文字与按钮底色对比度建议 **≥ 4.5:1**。

### 2.2 颜色使用原则
- 不仅靠颜色传达状态：错误/成功/警告需搭配图标与文案。
- 避免低对比浅灰文字（如 #999 在白底）作为主要信息。
- 减少高饱和、强闪烁、相邻高冲突色组合（降低视觉刺激）。

### 2.3 信息层级
- 通过“字号 + 字重 + 空间 + 颜色”组合建立层级，不只靠颜色。
- 关键行动（如“下一步”“确认”）在视觉上突出且位置稳定。

**设计理由**：对比不足和过度依赖颜色会导致识别失败，尤其在弱视、白内障或环境光复杂时更明显。

---

## 3. 点击热区与操作容错（Touch Target & Error Tolerance）

### 3.1 热区尺寸
- 主要可点击元素最小热区：**44×44 px**（推荐 48×48 px）。
- 相邻可点击元素间距建议 **≥ 8 px**，高误触区（底部工具栏）建议 **≥ 12 px**。

### 3.2 可点击性反馈
- 所有可点击元素具备明显状态：默认 / 按下 / 禁用。
- 点击后即时反馈（颜色变化、微动效、加载态）。
- 禁用按钮必须说明原因（例如“请先填写手机号”）。

### 3.3 容错机制
- 关键高风险操作（删除、支付、提交不可逆）需二次确认。
- 提供“撤销”或“返回上一步”能力（在可行场景下）。
- 表单填写尽量保留用户输入，避免错误后整页重置。

**设计理由**：手部精细动作能力下降时，较大的热区和明确反馈能显著减少误触与焦虑感。

---

## 4. 流程简化与认知负担控制（Flow Simplification）

### 4.1 任务路径控制
- 高频任务优先做到 **3 步内完成**（如查信息、提交申请、联系客服）。
- 复杂流程拆分为分步式，显示“当前第 X 步 / 共 Y 步”。
- 同屏仅保留当前任务必要信息，减少干扰项。

### 4.2 文案与信息组织
- 使用短句、口语化表达、避免专业术语。
- 一次只提出一个核心决策，减少并列选项数量（建议 3–5 个内）。
- 关键说明前置（例如费用、时效、需要材料）。

### 4.3 默认与自动化策略
- 合理预填已知信息（姓名、手机号），减少输入。
- 给出推荐默认选项，并允许用户修改。
- 使用明确的主按钮文案（如“确认并继续”优于“提交”）。

**设计理由**：简化流程可降低短时记忆压力，减少“看不懂/不知道下一步”的中断行为。

## 5. 错误提示与引导（Error Messaging & Guidance）

### 5.1 错误提示原则
- 错误提示要包含三要素：
  1) **发生了什么**（例如“身份证号格式不正确”）
  2) **为什么**（例如“应为18位数字，末位可为X”）
  3) **怎么改**（例如“请检查并重新输入”）
- 就近提示：错误信息出现在对应字段附近，而非仅顶部弹窗。
- 文案避免责备语气（不用“你输入错了”，改为“该项格式有误”）。

### 5.2 可恢复性
- 出错后保留已填内容，仅标记问题字段。
- 提供“一键重试”“联系客服”“查看示例”等补救路径。
- 网络异常场景提供明确状态与建议动作（检查网络/稍后重试）。

### 5.3 引导与帮助
- 关键步骤提供“示例”“填写说明”“常见问题”入口。
- 支持人工协助通道（电话、在线客服），入口固定且易发现。
- 对首次使用用户提供轻量新手引导（可跳过、可再次查看）。

**设计理由**：老年用户在错误场景更易放弃任务，清晰、可执行的纠错路径是完成率关键。

---

## 6. 可访问性基础要求（A11y Baseline）

- 使用语义化 HTML（button 用于按钮、a 用于链接）。
- 所有交互元素可通过键盘访问（Tab 顺序合理，焦点可见）。
- 表单必须有 label 与 input 正确关联（for/id）。
- 图标按钮需提供可读名称（aria-label）。
- 图片需有 alt（装饰图可空 alt）。
- 不通过颜色单独表达状态，需文字或图标补充。

## 7. 适老化验收检查清单（给 FE/PM）

### 视觉可读性
- [ ] 正文字号 ≥ 16px，默认推荐 18px
- [ ] 正文对比度 ≥ 4.5:1
- [ ] 支持字号放大且不破版

### 操作易用性
- [ ] 主要点击热区 ≥ 44×44 px
- [ ] 相邻操作间距充足，误触率可控
- [ ] 关键操作有反馈、危险操作有二次确认

### 流程体验
- [ ] 高频任务路径控制在 3 步左右
- [ ] 分步流程有进度提示
- [ ] 关键文案易懂、选项数量受控

### 错误与支持
- [ ] 错误提示包含“原因 + 修复方式”
- [ ] 出错后可恢复，不清空已有输入
- [ ] 提供人工帮助入口与重试路径

---

## 8. 后续落地建议
- 在设计系统中增加“适老化模式”设计令牌（字号、间距、热区、对比色）。
- 对核心流程开展 55+ 用户可用性测试（任务成功率、误触率、平均完成时长）。
- 将本草案转为组件级规范（按钮、表单、弹窗、列表）并纳入 FE 验收标准。
