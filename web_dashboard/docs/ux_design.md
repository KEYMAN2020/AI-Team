# n8n_0524_0026 银发友好交互规范与页面信息架构

## 1. 分析产品需求

### 1.1 目标用户与核心约束
- 目标用户：银发人群（视力减弱、精细操作能力下降、数字产品经验不均）。
- 体验目标：
  1) 看得清（高对比、大字号）
  2) 点得准（大点击区、低误触）
  3) 看得懂（文案直白、信息层级浅）
  4) 做得完（一步一操作、明确反馈）

### 1.2 本次输出范围
- 交互规范：高对比度、18px+ 正文字号、一步一操作流程。
- 页面信息架构：
  - 首页
  - 活动
  - 我的订阅
  - 个人中心

### 1.3 关键设计原则（决策与理由）
1. **单屏单目标**：每个页面优先一个主任务，减少认知负担。
2. **主操作固定位置**：主按钮放底部安全区域（拇指易达），降低寻找成本。
3. **信息先结论后细节**：先给“我能做什么”，再展示补充信息，提升决策效率。
4. **可逆与可恢复**：关键动作均支持确认、撤销或返回，降低操作焦虑。
5. **显性状态反馈**：加载/成功/失败状态均可见可读，避免“没反应”的不确定感。

## 2. 用户旅程（User Journey）

## 用户旅程
1. 用户进入应用（首次或回访）
   - 首次进入：看到“简明引导卡片”（可跳过），说明四大入口用途。
   - 回访：直接进入首页，展示“今日可做事项”（活动报名、订阅查看）。

2. 用户从首页选择目标
   - 目标A：参加活动 → 进入“活动”页面
   - 目标B：管理已订阅内容 → 进入“我的订阅”
   - 目标C：修改个人信息/无障碍设置 → 进入“个人中心”

3. 用户完成任务（一步一操作）
   - 活动报名流程：浏览活动列表 → 打开详情 → 点击“立即报名” → 二次确认 → 成功反馈
   - 订阅管理流程：查看订阅列表 → 打开订阅项 → 执行暂停/续订 → 结果反馈
   - 个人中心流程：进入设置项 → 修改单一字段 → 保存 → 成功提示

4. 用户返回首页或继续下一任务
   - 成功后提供两种明确出口：“返回首页”“继续查看”。

### 异常路径
- 网络异常：展示大字错误卡 + “重试”主按钮 + “返回首页”次按钮。
- 表单校验失败：就地提示（红色高对比文本 + 图标），并自动聚焦到错误项。
- 重复提交：按钮进入 loading 且禁用，文案改为“提交中，请稍候…”。
- 误操作风险（取消订阅/退出报名）：弹出确认层，提供“我再想想”（默认焦点）与“确认”。

## 5. 页面设计详情（文字线框）

#### 页面：首页（`/home`）
```text
┌──────────────────────────┐
│ 顶部栏：问候语 + 日期      │
├──────────────────────────┤
│ 今日可做事项（卡片）       │
│ - 待报名活动 2 项          │
│ - 待处理订阅 1 项          │
├──────────────────────────┤
│ 主入口大按钮区（2x2）      │
│ [活动] [我的订阅]          │
│ [个人中心] [联系客服]      │
├──────────────────────────┤
│ 最近活动推荐（横向卡片）   │
└──────────────────────────┘
[底部导航：首页 | 活动 | 我的订阅 | 个人中心]
```
- 交互重点：
  - 主入口按钮最小高度 52px，图标 + 文字双编码，降低识别难度。
  - “今日可做事项”卡片可点击跳转对应任务，缩短操作路径。

#### 页面：活动（`/events`）
```text
┌──────────────────────────┐
│ 顶部栏：返回(可选) + 标题   │
├──────────────────────────┤
│ 筛选条：时间 | 类型 | 就近   │
├──────────────────────────┤
│ 活动列表（大卡片）          │
│ [活动标题]                 │
│ 时间/地点/剩余名额          │
│ [查看详情] 按钮             │
│ ...                        │
└──────────────────────────┘
```
- 交互重点：
  - 筛选采用“单选弹层”，一次只改一个条件（一步一操作）。
  - 卡片仅保留关键字段，详情在下一页展开，避免信息拥挤。

#### 页面：我的订阅（`/subscriptions`）
```text
┌──────────────────────────┐
│ 标题：我的订阅              │
├──────────────────────────┤
│ 状态筛选：全部/进行中/暂停  │
├──────────────────────────┤
│ 订阅列表卡片                │
│ 名称 + 到期时间 + 当前状态   │
│ [管理订阅]                 │
│ ...                        │
└──────────────────────────┘
```
- 交互重点：
  - 状态标签使用高对比色 + 文本（不只靠颜色区分）。
  - 每条卡片只提供一个主动作“管理订阅”，降低决策复杂度。

#### 页面：个人中心（`/profile`）
```text
┌──────────────────────────┐
│ 头像(可选) + 昵称          │
├──────────────────────────┤
│ 信息区                    │
│ [个人资料]  >             │
│ [账号安全]  >             │
│ [无障碍设置] >            │
│ [通知设置]  >             │
├──────────────────────────┤
│ 退出登录（次级风险按钮）    │
└──────────────────────────┘
```
- 交互重点：
  - 列表项右箭头 + 整行可点，提高命中率。
  - “无障碍设置”前置，符合银发用户长期可用需求。

## 6. 银发友好交互规范（FE实现基线）

### 6.1 视觉与排版
1. **字号**
   - 正文最小 `18px`
   - 次级说明最小 `16px`（仅辅助信息）
   - 页面标题建议 `24px`，区块标题 `20px`
2. **行高**
   - 正文行高 `1.5~1.7`
3. **对比度**
   - 正文文本与背景对比度 >= `7:1`
   - 大号文本（>=24px 或 >=18px 粗体）对比度 >= `4.5:1`
4. **色彩策略**
   - 不用浅灰正文；正文默认深色（近黑）+ 浅底。
   - 语义色必须配合文字/图标，不允许“仅颜色传达状态”。

### 6.2 触控与布局
1. 点击区域最小 `48x48px`，建议 `52x52px`。
2. 相邻可点击元素间距 >= `12px`，避免误触。
3. 底部主按钮固定于安全区，单页仅 1 个主按钮。
4. 可滚动区域避免嵌套滚动，保证操作可预期。

### 6.3 一步一操作流程
1. 单次页面只完成一个核心动作（选择、确认、提交分步进行）。
2. 关键任务分为“输入页 -> 确认页 -> 结果页”。
3. 每步顶部展示当前步骤标题（例：`第2步：确认信息`）。
4. 上一步数据默认保留，可返回修改。

### 6.4 反馈与状态
1. 所有按钮点击后 100ms 内有视觉反馈（按压态/loading）。
2. 提交中：按钮禁用 + 文案改为“处理中…”。
3. 成功：页面内成功提示 + 下一步按钮。
4. 失败：原因简述 + 可执行动作（重试/联系客服/返回）。

## 7. 可访问性要求（A11y）

1. **键盘导航**
   - Tab 顺序符合视觉顺序。
   - 焦点态清晰可见（至少 2px 高对比描边）。
   - 弹层打开后焦点陷阱生效，Esc 可关闭（非强制确认场景）。

2. **屏幕阅读器支持**
   - 所有按钮具备可读名称（`aria-label` 或可见文本）。
   - 输入项关联 label 与错误提示（`aria-describedby`）。
   - 状态更新（成功/失败）使用 `aria-live="polite"` 区域播报。

3. **语义化结构**
   - 使用 `header/main/nav/section/footer`。
   - 列表使用 `ul/li`，避免纯 `div` 堆砌。

4. **动效与可控性**
   - 尊重 `prefers-reduced-motion`，减少位移与闪烁动画。
